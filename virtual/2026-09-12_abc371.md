## A の振り返り（21分・2WA）

`A < B` などの比較3つから、真ん中の人を答える問題。

**やったこと**: 配列/ハッシュを用意して、各比較ごとにスワップ → 2WA

**なぜ壊れたか**: **スワップは処理順に依存する。**
各ペアを1回ずつ適用しても整列しない。1回目のスワップで位置と名前がずれ、
2回目以降の入れ替えが元の比較と別の意味になる。
サンプルは通ってしまうので、WAで初めて気づく。

**最終的に通したもの**: 6通りの場合分け（矛盾する入力は来ないと明記されている）

**本来の解法**: 各人について「自分より大きい人の数」を数える。真ん中は必ず1。

**教訓**:
> **入れ替えは順序に依存する。数え上げは依存しない。**
> 比較結果が複数与えられたら、まず数える方向を探す。
> 場合分けが 2^N 通りになりそうなら、それは数える問題。

## D の振り返り（AC）

**型**: 累積和 + 二分探索

本番中に即座に型が当たった。実装の境界処理で苦労した。

**苦労した点**: 座標の間に l, r が来るケース。
`xs[left] > r` の判定（区間内に点が1つもない）が抜けると壊れる。**自力で発見**。

**境界の書き方**:
- `bsearch_index { it >= l }` → l 以上の最小
- `bsearch_index { it > r }` → r より大きい最小。その手前が r 以下の最大
- `nil` のときは「全部が r 以下」なので末尾

```ruby
n = gets.to_i
xs = gets.split.map(&:to_i)
ps = gets.split.map(&:to_i)
i = 0
s = [0] + ps.map { i += it }

q = gets.to_i
q.times do
  l, r = gets.split.map(&:to_i)
  left = xs.bsearch_index { it >= l }

  if left.nil? || xs[left] > r
    puts 0
    next
  end

  right_gt = xs.bsearch_index { it > r }
  right = right_gt ? right_gt - 1 : n - 1

  puts s[right+1] - s[left]
end
```

- **二分探索の境界処理が繰り返しの詰まりポイントかもしれない。**

  3回目が来たら、型として集中的に潰す
